# Phase 1：需求澄清

## 本轮请求

> $tdd 我想做一个Python标准库内存待办清单，只支持新增标题和按创建顺序列出，标题去首尾空白，空标题拒绝。现在先陪我理清需求，不写代码。

使用 Skill：`仓库/skills/tdd/SKILL.md`。

## 面向用户的本轮产物

目标是一个仅在当前进程内保存数据的待办清单，使用 Python 标准库，支持新增标题和列出标题两项操作。

已确认规则：

- 新增时去掉标题首尾空白，保留中间空白。
- 去掉首尾空白后若标题为空，拒绝新增；原清单不变。
- 列出时按新增成功的先后顺序返回，保留规范化后的标题。
- 数据保存在内存中，不要求跨进程或重启后保留。
- 此轮只澄清需求，不写业务代码、接口骨架或测试。

验收场景：

| 起始状态 | 动作 | 可观察结果 |
| --- | --- | --- |
| 空清单 | 列出 | 空序列 |
| 空清单 | 新增 `买牛奶`，随后列出 | 仅有 `买牛奶` |
| 空清单 | 新增 `  买牛奶  `，随后列出 | 仅有 `买牛奶` |
| 空清单 | 新增 `读  书`，随后列出 | 中间两个空格保留 |
| 已有 `第一项` | 新增 `第二项`，随后列出 | `第一项`、`第二项`，顺序不变 |
| 任意清单 | 新增空字符串或仅含空白的字符串 | 拒绝新增，原清单不变 |

建议默认，尚未作为用户确认的规则：

- 暂允许相同标题重复添加，每次成功新增都占据一个顺序位置；用户没有要求去重。
- 标题以字符串为输入；其他类型不扩展为本轮业务需求。
- “拒绝”的具体接口表达（例如异常类型）、调用方式及返回容器形态，留到接口设计时决定。

范围外：删除、修改、完成状态、优先级、搜索、持久化、界面、网络接口及并发。

目前没有阻碍理解目标的业务问题。后续若用户希望收紧重复标题规则，再据其指令调整；本轮不为常规接口选择增加确认步骤。
