# 历史报告：八入口版（e610697）

测试日期：2026-11-25。受测版本见 [Skill 文件 SHA-256 清单](skill-sha256.json)。

结论：8 个 Skill 均通过格式校验；3 个隔离子 Agent 实际执行了默认批量、测试审阅后续做及全部单步入口，观察结果符合本轮约定。主 Agent 检查产物并复跑 6 组保存的样例，全部与预期结果一致。其中两组故意保持失败，以验证审阅停点和只读验收，不代表待修复缺陷。

## 测试方式

- 子 Agent 不继承主会话，接收 Skill 路径、实际用户任务和隔离工作目录；没有提供参考实现或评分答案。
- 使用 Python 3.9.6 标准库 `unittest`，不依赖第三方测试框架。Skill 格式校验使用官方 `quick_validate.py`，环境为 Python 3.12.14、PyYAML 6.0.4。
- 每个样例在独立进程运行，避免同名模块相互影响。子 Agent 的完整过程保存在本地忽略目录 `black/behavior-tests/`；可公开的证据与最终样例随仓库保存。

## 观察结果

| 使用场景 | 实际结果 | 判断 |
| --- | --- | --- |
| 默认 batch：内存会议室预约 | 逐行为写测试、运行、实现；最终 6 项通过，编译检查通过；相邻预约、不同房间直接通过时没有破坏已有实现 | 符合 |
| batch：先写完整测试再审阅 | 无既有实体时先补最小库存接口；写出并运行 10 个测试方法，33 个断言失败（含子场景），0 个运行错误；停在骨架，未实现业务 | 符合 |
| 审阅后继续实现 | 沿用原库存测试，10 项全部通过；测试和审阅阶段证据的 SHA-256 不变 | 符合 |
| scope / case 单独调用 | 只形成需求和场景，没有生成业务代码、测试或持久化架构 | 符合 |
| contract 单独调用 | 只创建 `TodoList` 最小接口和占位方法；导入检查通过，没有自动实现或补测试 | 符合 |
| red：新增测试已绿 | 正确的字符串归一化实现保持不变；新增空白输入测试后共 2 项通过，停在审阅点 | 符合 |
| green 单独调用 | 先实际观察 2 个占位错误，再实现通用求和；2 项通过，没有修改测试 | 符合 |
| refactor 单独调用 | 只整理局部变量名；前后 2 项均通过，公开接口和测试不变 | 符合 |
| verify：验收错误实现 | 1 项明确业务断言失败；实现、测试的 SHA-256 均不变，没有自动修复 | 符合 |

以上未观察到需要修改 Skill 的行为偏差，因此没有为了测试而添加额外约束。

## 可复现验证

在仓库根目录运行：

```sh
python3 -B tests/replay.py
```

主 Agent 复跑结果：

```text
PASS booking: (6, 0, 0), exit=0
PASS inventory-review: (10, 33, 0), exit=1
PASS inventory-complete: (10, 0, 0), exit=0
PASS red-already-green: (2, 0, 0), exit=0
PASS verify-read-only: (1, 1, 0), exit=1
PASS green-refactor: (2, 0, 0), exit=0
```

括号依次表示测试方法数、失败数、错误数。回放脚本自身退出码为 0，因为审阅骨架和只读验收样例的失败符合预期。其余 4 组共 20 个测试方法全部通过。`subTest` 可在一个测试方法中产生多个失败。

`tests/replay.py` 仅重放保存的项目样例，不会再次调用 AI；它不能单独证明 Skill 总能正确选择执行节奏。

## 验证边界

本轮是小型、单进程、内存业务的行为抽样，不是所有语言、所有 Agent 或所有项目的可靠性证明。当前环境没有 Go，未执行 Go 编译、Go 测试或竞态检测；也未覆盖网络依赖、数据库事务、并发业务、环境损坏和中途需求变更等场景。格式校验不能代替行为验证，样例通过也不能代替实际项目验收。
