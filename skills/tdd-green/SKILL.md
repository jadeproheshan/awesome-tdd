# 实现目标行为

## 本步

检查目标测试、已确认需求和当前真实失败。先运行相关测试建立基线；若已有实现正确且测试通过，说明已覆盖，不为了产生改动而改代码。

以通用且足够小的实现满足行为及边界，不只匹配样例。运行目标测试与受影响回归，修复本次实现造成的问题；保留错误语义和现有已确认行为。

测试缺失时，若行为清楚且用户授权包含补测试，可先补最小测试；否则指出缺失并停在所选范围内，不自动回到需求澄清或启动整套流程。测试预期疑似错误时给出需求依据，不私自降低要求。

## 停点

目标行为及相关回归通过后停止，说明改动和验证。不自动进入额外功能、发布或非必要重构；没有实际通过时不声称完成。

## 执行约定

- 优先遵循用户本次指定的范围、节奏和停点；本技能的默认流程是可调整的起点，不是强制用户遵循的仪式。不把“我指定了一个步骤”解释成授权运行全部步骤。
- 先读项目说明、现有需求、相关代码和测试，复用已有契约。业务规则存在影响正确性的歧义时再询问；不要猜测关键规则，也不要重复确认已经明确的事项。
- 仅修改授权范围内的文件，保护现有改动。遵循项目的生成文件位置规则。只有用户要求保存过程记录时才新增记录文件，不强制创建工作台或新架构。
- 测试预期来自需求或已确认行为。实现阶段不通过弱化断言、删除覆盖或硬编码样例来过关；发现原测试与需求冲突时说明依据，再按用户指令处理。
- 使用项目真实可用的测试命令。区分行为失败、编译失败、环境阻塞与已有通过；不伪造执行结果，不为制造 Red 故意破坏正确实现。无法运行时明确未验证的范围。
- 输出以本轮行为、关键改动、实际验证和当前停点为主，简洁即可；未执行的后续步骤只列为可选下一步。
