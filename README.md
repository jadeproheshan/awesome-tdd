# Awesome TDD

用于 AI Coding 的中文 TDD Skills。七个步骤可单独调用，也可以批量推进；默认流程可被当次自然语言指令调整。适用于 Go、Python 等项目，不绑定框架或测试工具。

## 单步调用

| 入口 | 用途 | 默认停点 |
| --- | --- | --- |
| `$tdd-scope` | 澄清需求、规则、范围与验收标准 | 需求清楚后停止，不实现 |
| `$tdd-case` | 选最小行为、列可观察预期 | 场景清单，不写代码 |
| `$tdd-contract` | 定义最小接口、实体和必要骨架 | 不实现业务逻辑 |
| `$tdd-red` | 写测试并实际运行，解释结果 | 测试审阅点，不实现 |
| `$tdd-green` | 实现明确行为，验证相关回归 | 通过后停止 |
| `$tdd-refactor` | 保持行为的结构整理 | 不扩功能 |
| `$tdd-verify` | 整体验收、回归与交接 | 默认只检查，不修复 |

不要求线性走完七步。已有需求或契约直接复用；一次只调用某一步时，不自动跑完整套。

## 批量入口

```text
$tdd-batch 基于已确认规则，实现成功预约、冲突拒绝、相邻时段允许和取消释放。直接做完。
```

默认按依赖顺序逐行为执行“最小契约 → 测试 → 真实运行 → 实现 → 验证”，最后整批回归，不需要逐步确认。

```text
$tdd-batch 先把全部测试写好跑一下，我看完再实现。
```

这会写出可审阅的测试和必要骨架，报告真实结果，在业务实现前暂停。审阅后说“继续实现”，即可沿用已确认测试继续。也可要求逐行为审阅、只做部分行为或其他节奏，无须填写参数表。

## 关键约定

- 测试预期由需求决定，不能为过关删断言或改预期。
- 实体不存在时先推导最小契约；不强制先完成整套架构。
- 已经通过的新测试如实记录，不破坏实现制造 Red。
- 区分编译或环境错误、目标行为失败、已通过与未验证。
- N 个行为不要求 N 个测试或 N 个函数；按业务可观察结果组织。
- 单步默认到站停止；batch 默认继续，但遵循用户明确的停点和范围。

## 安装

每个 `skills/tdd-*` 都是完整独立 Skill，可分别复制到支持 Agent Skills 的工具目录。Codex 全局目录通常是 `~/.codex/skills/`；其他工具按自己的发现规则安装。

使用 Codex 自带的 skill-installer 时，可请求：

```text
从 jadeproheshan/awesome-tdd 安装 skills/ 下的全部八个 TDD Skills 到全局目录。
```

安装后在新的会话轮次使用 `$tdd-batch` 等入口。测试过程与边界见 [测试报告](reports/测试报告.md)。
